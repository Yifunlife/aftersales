# 企业微信工单交接提醒

当前部署默认关闭，无企业微信账号或应用配置时不会发送。开关入口：员工工作台右上角 **交接提醒设置**（仅管理员）。

## 接入

1. 企业管理员自行注册企业微信、完成所需主体验证并将员工加入通讯录。
2. 在企业微信管理后台创建自建应用“售后工作台”，将需要通知的员工加入应用可见范围。
3. 在 ECS `/etc/yifun-aftersales/runtime.json` 及维护源配置中增加 `wecom` 对象，字段为 `corpId`、`agentId`（正整数）、`secret`、`publicUrl`（`https://aftersales.shyiwan.com`）。配置文件权限保持原有服务专用限制。Secret 不得提交 Git、写浏览器或输出日志。
4. 在企业微信应用的企业可信 IP 中配置本服务器实际公网出口地址。当前 ECS 公网地址为 47.116.18.155，启用前从服务器验证实际出口；仅按需完成域名等后台要求，不改其他应用设置。
5. 只重启售后服务。管理员在网站绑定员工的企业微信 **成员账号/UserID**，不要用昵称或猜测工号。为生产、仓库等公共队列明确指定有相应岗位权限的接单人。
6. 先联调指定测试人员，再启用提醒，确认应用可见范围、接收设置、工单链接和岗位权限。当前未做真实企业微信联调，因为尚未注册企业微信。

官方接口说明：https://developer.work.weixin.qq.com/document/path/90236

## 行为

- 工单保存成功时，同一数据库事务中记录交接事件；新登记正式提交、客户申请检查交审核、整单审核转交、阶段流转或负责人变化触发提醒。普通保存、草稿和关闭不提醒。
- 开关关闭期间的事件为 `paused`，启用不会补发。管理员可逐条明确重试仍有效的记录。
- ECS 每分钟检查待发送记录，通过企业微信官方自建应用消息接口发送；发送失败退避重试，六次后停留失败状态。数据库租约避免多个进程同时发送，平台重复检查降低网络超时重发风险，不能承诺严格恰好一次投递。
- 指定个人时必须匹配唯一启用员工及对应岗位，并绑定成员账号；只有已知部门队列占位值才使用该环节配置的固定接单人。无人绑定、重名、错误岗位或无队列配置显示“需要配置”，不会隐式群发。
- 旧提醒在工单阶段/负责人已变化或已有更新交接记录时取消。
- 消息仅包含工单编号、环节和登录链接。客户名称、问题详情、联系方式、费用、照片等不外发。消息链接不是访问凭证，仍须员工登录和岗位校验。
- “已提交企业微信”只表示接口接受，不表示已读或接单。此版本没有新增接单确认或超时催办功能。
- 不回填历史工单，也不改员工现有登录密码。管理员绑定/开关/队列修改保留审计。

## 验证

`node tests/work-notifications.mjs`：事务版本守卫、默认关闭与历史不补发、幂等、租约、公共队列显式接单人、发送失败/部分无效成员、隐私、角色与跨站限制。
`node tests/customer-intake.mjs`：原有工单登记、转交、权限和持久化回归。
